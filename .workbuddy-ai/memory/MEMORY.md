# catOS 项目长期记忆

- 2026-09-15 用户明确最终前端目标：用户能够在同一个网页中切换 Live／Demo。研究工作台或只读监控是可能的阶段性交付，不是最终产品功能上限。
- 此目标尚未定案前端技术栈、切换时运行中的 Bot 如何处理、是否允许两环境同时运行或具体启停流程；不构成读取凭证、启动 Live 或发送真实交易的授权。
- 2026-09-15 用户交接将新研发方向改为同合约多 Bot、同向/反向的本地逻辑分仓（Virtual Lots），排除等待普通分仓 API、每方向最多一 Bot、每 Bot 独立子账户；此方向取代旧 P8 的等待路线，但不代表已解除现有 v1 的运行限制。
- 本次先交付 S1 数据结构与三类意图（OPEN_LOT/CLOSE_LOT/UPDATE_LOT_PROTECTION）规格和测试清单，不直接重构交易链路。新路线以 Gross 而非多空净额作为逻辑曝险预算；本地 TP/SL 不具备离线保护或保证金隔离保证，执行模式与 P6 兼容必须另行定案。
- 交接文字提出日损 3%/5%，实际代码及既有 P5 默认是 10%/20%；不可把交接称作当前事实或静默覆盖已有配置/清除锁存。S1 不修改门槛，后续迁移需明确处理。
- 2026-09-15 用户要求先检查 OKX Agent Trade Kit，若不能解决自定义多 Bot 分仓再用本地 Virtual Lots。核对官方 github-main 合约工具后，其开仓/平仓仍封装常规 trade/order 与 trade/close-position，未提供指定普通 Bot 子仓的写入参数；Grid/DCA 的 algoId 仅属对应机器人产品，不是任意 Python 策略仓位容器。因此 catOS 继续本地 Lot 账本路线，Trade Kit 不作为分仓替代或第二交易出口；未授权安装、连接账户或改持仓模式。
- 2026-09-15 用户明确同意本地虚拟分仓，要求先分析业界做法并讨论，不直接开始实现。双向聚合执行、内部净额抵销、交易所保护方案尚未定案。
- 同日官方文档核查纠正：缺普通分仓 API 不意味着逐 Lot 保护必须全部本地。OKX order-algo 提供 sz/posSide、TP/SL、algoId 等数量型条件单能力，但不认识 catOS Lot，不能据此保证跨 Bot 隔离或无竞态。交易所保护可作为候选，须处理剩余量同步、撤改单/触发竞态和重启对账；既有 P6 不自动撤销。
