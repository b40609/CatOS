# P6：每 Bot 災難停損政策定稿

2026-09-12，依使用者最新決策。政策定稿後，已另獲授權完成 [P6 本機模擬核心](protection-simulation.md)，包含建立／更新／取消／UNKNOWN 與成本更新。執行參數已確認採 mark 觸發、tick 向提早觸發方向取整、0% 停用等待取消終態；未啟動交易所適配、I-b 或 J。官方能力與區域差異保留在 [I-a 研究](okx-readonly-contract.md)，不能把本文件視為指定帳戶的支援證明。

## 已確認政策

| 項目 | 定稿 |
|---|---|
| 設定範圍 | 每個 Bot 可獨立設定災難停損比例，不同幣種可使用不同數值；不共用一個帳戶級災難比例 |
| 預設 | 0% = 不啟用災難停損；停用是有效設定，不因沒有保護單而視為建立失敗 |
| 保護形式 | OKX 交易所端整倉停損，作為斷線／主機故障時最後保險；僅涵蓋 Bot 已歸因且獨佔的受管部位 |
| 正常交易 | 仍由策略自身停損處理；災難停損不取代策略規則 |
| 帳戶風控 | 不取代 Soft／Hard；即使災難比例為 0%，帳戶日損設定、鎖存及人工恢復規則照常有效 |
| 成本變更 | 部位平均成本改變時更新災難停損，不固定綁首次入場價 |
| 建立／更新失敗 | 禁止繼續增加曝險並告警；不做自動減持，不把失敗轉成自動去槓桿或主動市價平倉 |
| 其他減倉原因 | 策略合法減倉、帳戶 Hard／人工 Kill 的既有職責仍有效；禁止的是以「保護失敗」自行發動減持 |

此決策取代 I-a 的候選表與「保護缺口超時後自動減持」建議。未批准自動撤銷殘留進場單，也沒有新增儲存失效繞過持久化的交易出口。

## 資料與生命週期契約

比例由使用者配置並由 Supervisor 保存，使用 Decimal／SQLite TEXT，不由 Worker 覆寫。部位平均成本由已核實成交與部位對帳提供；不能採用 Worker 自報成本作交易所保護依據。

對平均成本 A、災難比例 r，多倉參考停損價為 `A × (1 − r)`，空倉為 `A × (1 + r)`；r=0 時不生成保護價格或委託。這是價格比例，不是槓桿後報酬率或帳戶日損率。實際送單仍須核對 tick、有效價格、方向、帳戶模式及 API 支援。

啟用且首次出現已核實部位時，須能分辨「待建立、有效、待更新、失敗或未知」。新增成交改變平均成本，即重新計算；減倉若沒有改變成本，也必須核對整倉保護仍覆蓋當前部位。不得把送出／修改 ACK 當成有效保護證據，UNKNOWN 不盲目重送。

建立／更新失敗或結果未知時，保留責任紀錄、關閉增倉並告警；不自動減持。若先前保護仍存在，不聲稱它已更新至新成本；離線時只能依交易所實際已存在的委託處理。恢復連線先核對保護與部位，不因連線恢復就假設缺口消失。

固定 tag `41cb53c54d6dABDE`、唯一 Supervisor 交易出口、cross／net、單幣單 Bot 與陌生責任不接管規則繼續適用。正常平倉、保護觸發、剩餘進場單與重啟必須共用歸因及完整終態對帳；不得因本地空倉就釋放全部責任。

## 已確認執行參數與後續驗證

已確認：`slTriggerPxType` 採 mark；停損價按 tick 向提早觸發方向取整（多倉向上、空倉向下）；既有保護下把比例改為 0% 時採取消確認，完整取消終態前保留責任、禁止增加曝險，UNKNOWN 持續告警與查詢。這三項已成為本機 `Config` 預設，但不會把 0% 自動改成正比例。實際帳戶對 mark 觸發與整倉 algo 的支援仍須在後續適配驗證；`cxlOnClosePos` 仍未定為必要依賴。

0% 表示沒有這層交易所災難保護；策略與帳戶風控在主機停機時無法繼續由本機執行。非零比例也不保證帳戶損失精確止於指定百分比。

## 驗收契約與階段

| 案例 | 必驗行為 |
|---|---|
| Bot A=0%、Bot B 使用明示非零測試比例 | A 不建單，B 依自己的比例建立；不互相套用配置 |
| 同幣種出現第二 Bot | 既有單幣獨佔拒絕，不用災難保護規避所有權 |
| 多／空部位的平均成本改變 | Decimal 重新計算，再核實更新結果；不能只改本地顯示 |
| 首次部分成交、更新 ACK 遺失或失敗 | 無法核實保護時禁增倉並告警；沒有因失敗而發出的自動減持單 |
| 災難停損停用但觸發帳戶 Hard | 帳戶 FLAT／鎖存仍生效，不受 Bot 災難比例影響 |
| 策略平倉與保護觸發競爭 | 不穿零、不重複歸因，普通／條件責任全對齊後才能結案 |
| 主機重啟或部位混入陌生責任 | 先對帳；不自動接管或處置陌生部位 |

上述建立／修改／失敗／停用等案例已有本機合成驗證，詳細實測範圍見 [P6 模擬契約](protection-simulation.md)。行情觸發後子委託／成交的完整閉環與真實交易所驗證尚未完成，不把本機測試算成 Demo 證據。
