更新日期：2026-09-12。使用者已依序啟動 D／E／F／G，本機模擬底座四片均已完成。G 以 `3e41c97` 為基線，專屬 27 個、受影響 E／F 模組 41 個，共 68 個測試通過。實際介面見 [Worker 文件](worker.md)、[Supervisor 文件](supervisor.md)、[F 風控文件](risk.md)及 [G 執行文件](execution.md)。這不是 Demo／Live 驗收，待決金融政策未因此核准。

依據：[AGENTS.md](../AGENTS.md) 的 AUTONOMY、INVARIANTS、DESIGN BOUNDARY，以及[架構評估](../catOS-architecture-review.md)第 3、7–12、14–15 節。第 14 節的下一個里程碑為「v1 交易底座」，本次將它縮成可逐片驗收的離線版本。

## 1. 起點與階段目標

已驗收研究能力：Decimal Closed Bar 回測、預熱、Optuna 最小搜尋、CSV 匯入、離線 HTML 報告與研究 CLI。初始規劃時基線為 `24eb5df`、既有紀錄為 69 個全域測試通過；啟動 E 時已核對新基線 `3879c55`，使用者回報 93／93 全域測試通過，本輪未重跑全域套件。

規劃時另見未追蹤的 `catos/cli.py`、`catos/optuna_study.py`、`tools/fetch_okx_candles.py`。僅記錄其存在，未審查、執行或修改，不將它們算入已驗收基線或本階段依賴。

本階段目標：用單一合成帳戶、單 Bot、單合約、單週期，驗證「策略產生純資料意圖 → Supervisor 持久化與裁決 → 本機假交易所回報 → 故障後對帳」的最小閉環。沿用 Python 3.11+ 與 SQLite WAL，金融資料使用 Decimal／TEXT。

離線假交易所只接收測試腳本指定的受理、拒絕、部分成交、成交與查詢結果；它是執行故障測試替身，不是第二套績效回測引擎。研究版的下一根開盤成交假設維持原契約，不拿它模擬真實下單受理或保證金。

## 2. 切片順序與等比驗收

一次只實作、審查及交付一片。D → E → F → G；後片依賴前片的已驗收介面，表中的驗證成本是測試種類與整合範圍，不是工時承諾。

| 切片 | 當前具體失敗情境 | 最小做法與交付 | 驗收範圍／成本 |
|---|---|---|---|
| D：Worker 與 JSON 契約 | 策略卡死、輸出壞資料、舊程序回覆混入新一輪決策 | 普通獨立 Python Worker；長度前綴 UTF-8 JSON；版本、事件序號、世代與嚴格金融字串驗證；父程序持續排空輸出、逾時停用 | 編解碼單元測試＋少量真實 subprocess 故障測試；不接 DB／撮合 |
| E：單 Supervisor 與持久化 | 同一事件重播被接受兩次；程序死掉後所有權消失；兩個執行器同時管理同帳戶 | SQLite WAL、`synchronous=FULL`；單一寫入與資金提交序列；單實例／帳戶鎖、合約所有權；事件、checkpoint、意圖裁決、reservation 與 outbox 同筆提交；COMMIT 後才 ACK | 暫存 DB、兩程序競爭、提交前後中斷與重播測試；風控先用明示測試裁決，不開放交易 |
| F：已確認風控規則 | 在途額度漏算；反彈或重啟解除熔斷；Worker 卡住時無人處理風險事件 | Decimal 曝險純函式與 R／H／P 狀態更新器；鎖存、epoch、合法減倉；以獨立注入的合成風險快照驅動，不等待 Worker；接入 E 的原子裁決 | 純函式邊界測試＋風控／DB 整合；合成權益、mark 與保證金條件明示，非真實帳戶風控認證 |
| G：假交易所與恢復閉環 | 送出後 ACK 遺失、重複成交、撤單途中成交、重啟立即開倉 | 唯一 Supervisor 模擬出口；固定 tag；SUBMITTING→UNKNOWN、保留額度、成交去重、啟動對帳；以查詢證據決定後續狀態 | 腳本化假交易所＋受控程序中斷；驗證本機責任與狀態，不宣稱遠端 exactly-once |

E 已以 Windows 標準函式庫 file lock 完成同使用者、同 local-sim 帳戶互斥；鎖與 DB 路徑無關，且鎖檔固定綁定原 DB，防止重啟誤用空資料庫。第二個 Supervisor 被拒絕，程序退出後可重新取得同帳戶鎖；Worker 死亡不釋放 SQLite 合約所有權。沒有新增服務或跨平台原生封裝。

E 的同一交易包含事件消費位置、策略 checkpoint、意圖、裁決、額度保留與出站待辦；拒絕結果也需保存。金融提交前不 ACK、不出站。F 接入前，E 的測試裁決不可成為可執行開倉的替代風控。單一提交序列等待期間仍能接收 Kill／健康事件，G 出站前重查 epoch 與最新事實。

不預建通用事件溯源框架、虛擬帳本或策略分配器；只保存重播、歸因、鎖存及對帳必要資料。

## 3. D 切片契約（已完成）

### 介面與程序責任

- 父程序只持有已檢查策略的識別資料、版本與參數；策略 class 僅由 Worker 載入。首例使用既有 SMA 策略製品；不用任意路徑動態載入，也不把策略物件或 Python callable 傳過 IPC。
- Worker 只取得當前 Closed Bar、不可變帳戶視圖與必要設定；`update_indicators`、`ready`、`on_bar` 的時序沿用研究契約。`None` 維持原部位、`"0"` 代表平倉目標，不能混淆。
- 預熱事件只更新指標；輸出不得包含交易意圖，亦不可於正式期補送預熱意圖。父程序驗證 Worker 回覆，不能信任它自稱完成預熱。
- 每 Bot 同時最多一筆未確認事件；訊息帶協議版本、事件序號及 Worker 世代。Bot 身分由所屬 pipe 決定，拒絕訊息冒名與舊世代回覆。世代不納入 E 的穩定意圖主鍵。
- 採雙向 byte pipes、長度前綴分框及 UTF-8 JSON。拒絕重複／未知鍵、錯型別、非有限值、過長數字、過深巢狀與過大訊框；金融值直接由字串還原 Decimal，不經 Float。
- 每方向只有一個 writer；stdout 僅放協議訊框，stderr 獨立限量排空。訊框、佇列、pending、逾時與終止等待均有明示上限；上限以小型本地測試驗證，無吞吐最佳化目標。
- 子程序使用最小必要環境白名單，不複製整份父程序環境；測試只放假憑證哨兵。不得檢索真實金鑰、啟動憑證載入器，或向 Worker 提供交易 client、簽名器及寫庫介面。
- Worker 異常或協議違約時，父程序記錄結果並停用該 Worker，能繼續處理控制事件；D 不自動重啟接續交易、不聲稱具有持久化恢復能力。

### 策略狀態的具體缺口

現有 `Strategy` 只有指標更新與決策介面，沒有 JSON checkpoint 匯出／還原能力；不能用 pickle 或直接序列化任意 `__dict__` 補洞。

建議 D 為首個已檢查 SMA 製品提供窄範圍、明確欄位的 JSON 狀態轉接，回覆一筆完整 EventResult（本事件的目標意圖及狀態）。只保存 SMA 必要窗口等實際狀態，並驗證還原後的下一次決策一致。研究端和 Worker 使用相同策略邏輯，不另抄一份 SMA 計算。若必須調整既有策略介面，先列最小差異及受影響測試，不重構整個回測核心。

D 的狀態往返測試不等於耐久 checkpoint；E 才建立持久化輸入、提交及恢復邊界。尚未具備明確 JSON 狀態契約的其他策略，不宣稱能故障續跑。

### 專屬驗收與交付

1. 指定同一組合成 Closed Bar 與 AccountView，比對程序內參考結果及 Worker 結果；Decimal 原值、預熱時序、`None`／零目標與 JSON 狀態往返一致。
2. 分段讀寫、連續訊框、截斷、過大訊框、未知／重複鍵、金融 JSON 數字、NaN／Infinity、錯世代及錯序號均有明確結果。
3. 真實子程序崩潰、無回覆、stdout 協議污染及 stderr 大量輸出，不令父程序永久等待；測試結束後無遺留子程序。
4. 假憑證哨兵不出現在 Worker 環境或輸入；父程序不匯入策略實作。此項驗證應用邊界，不是 OS 惡意程式隔離測試。

候選檔案：`catos/ipc.py`、`catos/worker.py`、`catos/worker_host.py`，配對專屬測試與 `docs/worker.md`；SMA 狀態轉接放在最接近該製品的位置。檔名可在實作時調整，責任邊界不變。

D 完成條件：程式、契約文件與上述專屬測試通過即可交付。僅在實際修改研究或 SMA 介面時補跑受影響測試；不執行全市場回測、不以全域測試代替模組驗收。D 完成不自動啟動 E。

## 5. 階段出口與後續邊界

本機模擬底座須以小型合成場景證明：

- 同鍵同內容重播不重複接受；同鍵異內容停用 Worker；重啟不靠換世代產生新意圖。
- 同帳戶僅一個 Supervisor；單合約所有權跨 Worker 故障保留，只在空倉、普通及條件委託終結、無 UNKNOWN 且對帳完成後釋放。尚未支援的委託型別不得被假定不存在。
- 所有模擬 OKX SWAP 建單 payload（包含平倉與 Kill 路徑）由 Supervisor 強制注入 `"tag": "41cb53c54d6dABDE"`、限定 USDT-M／cross／net_mode；Worker 無覆寫能力。減倉不穿零、不繞過持久化。
- 風控裁決、意圖與額度原子提交；未 COMMIT 不 ACK、不出站；提交後、出站前出現的 Kill 或健康變化能阻止舊增倉待辦。
- SUBMITTING 重啟後視為 UNKNOWN；查無一次不解鎖、不換 ID 重送；重複成交不重複記帳，只有足夠對帳證據才能結案。
- Soft／Hard／Kill 在反彈、跨日、入金及重啟後仍鎖存；風險監控不依賴新 K 線或 Worker 回覆。獨立合成風險事件不構成細部 K 線回測。

持久化故障測試只聲稱覆蓋實際執行的程序中斷、I/O 錯誤與重播情境，不宣稱完成真實斷電或硬體耐久測試。資料庫失效時不繞過持久化下單；真實保證金、強平與交易所可成交性仍未驗證。

本階段不納入 Web UI／FastAPI、公開行情下載、私有 WS／REST、Telegram、真實憑證、Demo／Live 請求、Optuna 續跑或多策略分帳。Demo 開工前再查核適用的 OKX 官方介面並處理相關政策；本次規劃未重新查核外部 API。
