## 3. 原型不能直接沿用的語意

| 原型現況 | 與 catOS 的差異／使用者可能誤判 | 正式介面要求 |
| --- | --- | --- |
| PRODUCT 指向機構級、高頻／網格系統 | 不是目前個人本機、Closed Bar 主線 | 以研究、受管執行與解釋異常的工作流為主 |
| Hard 預設 15%，mock threshold 約 14.98% | catOS `risk.Limits` 已確認預設 20%，Soft 10% | 由後端讀取有效設定，不複製示意數值 |
| 單幣上限以權益 × 50% 換算，mock 表格比例也混入持倉分配／現金 | catOS 上限為有效槓桿上限 × 風控權益 × 單幣預算占比，含在途／UNKNOWN；例如權益 1000、3x、50% 是 1500 USDT，原型換算只有 500 | 後端提供 Decimal 預算／已占用／剩餘與明確分母，UI 不以 float 算交易或風控金額 |
| 風控 apply 只改 CATOS_DATA，卻 alert 已廣播 Supervisor；解鎖只改 browser state，卻 alert 已寫審計並恢復交易 | 把展示互動誤認為真正控制成功；現行研究頁雖有原型標示，提示語意仍不合適 | 有效設定、草稿與裁決分開；真正恢復須後端條件與明確操作，不能靠改門檻解除 |
| 總覽固定權益、三個 Bot、模擬 Agent 草稿及收益 | 與正在跑的 R4、真實研究任務無對應 | 無資料明示不可用／尚未接線；不能用零或正常替代未知 |
| 所有情境套同一套 Dashboard／Bots／Risk／Logs | 研究績效、模擬帳戶、交易所責任容易被混看 | 明示來源／環境，策略版本、研究 run、執行 run／Bot 與帳戶分別有身分 |

主頁不需要滿版 PID、hash、資料表或模組名稱；版本／完整來源放詳情。日常應先回答：哪些策略在跑、哪根訊號已處理、持倉與目標是否一致、還有哪些委託責任、為何不能增倉、下一步可做什麼。

保留黑／炭灰／低飽和金、高密度表格、等寬數字、可調分割與面板放大等合適的設計語言。重新安排資訊、名稱、控制與頁面；自由排版作工作區偏好，不讓復原／換頁／關閉面板成為策略指令。

```text
catOS                         量化交易 | Yaozi 情報
全站狀態：環境／資料來源／更新時間／需要處理的事件

量化交易
  總覽        當前執行、待處理原因、最近研究與資料品質
  策略研究    策略版本 → 設定／資料 → 回測 → 優化候選 → 保存結果
  執行工作台  選定 Bot/run → 訊號／部位／委託成交／心跳／執行限制
  帳戶與風控  權益基準／曝險預算／在途責任／latch／保護狀態
  事件紀錄    按 Bot、研究 run、執行 run、事件與原因追查

Yaozi 情報
  沿用其經查核的市場視角與單幣工作流；同源頁面、獨立資料品質
```

這是建議的資訊架構，名稱與細部流程仍可討論；首頁與版面自由度已由使用者選定，見第 6 節與 F1 規格。符合既有同站「量化交易／Yaozi 情報」決策，研究不再是另一套完整七頁原型網站。

### 研究工作區

左側選策略與版本；中央是當次研究，分設定、結果、成交、候選；右側詳情顯示執行快照與資料／成本假設。歷史結果有固定 run 身分，表單是下一次任務的草稿。MCP 任務共用同一結果清單；Agent 產生任務不表示有交易權限。新增任意策略／資料工作流另列尚未交付能力，不做看似可用的按鈕。

### 執行工作區

以後端 Bot／執行 run 為中心，頂部顯示來源環境、策略版本、最後訊號與下一根預期時間；中央看目標、實際部位、意圖裁決、委託與成交；側邊看阻擋原因、未決責任與近期異常。R4 第一版可接唯讀 evidence，後續才物化既有 Supervisor 的明確控制契約。

Worker 存活、資料新鮮、可以增倉、委託已終結是不同狀態。Worker 停止也可能仍有持倉／UNKNOWN／所有權。操作文案必須指出是否會影響部位或責任；不能只用一個暫停／停止燈號掩蓋差異。既有風控與恢復政策保持不變。

### 帳戶風控與情報

風控先呈現有效基準與阻擋原因，再看預算；設定草稿與已生效值分開，修改門檻不等於 re-arm。情報呈現來源時間、缺值與品質，研究與情報可同時開啟，情報不可用不影響策略生命週期；情報信號不直接變成交易。
