# 回測的 Soft／Hard 日損門檻觸發次數（診斷）

2026-11-12 實作。使用者同日同意，條件是保證金模型先完成（見 `docs/research-margin-model.md`）。

## 目的

帳戶的 Soft／Hard 日損會鎖存，只能人工恢復；回測不模擬鎖存。所以「這段歷史有幾天會觸發」就是實盤要手動介入的天數，讓使用者用自己策略的數字檢查門檻設得合不合理。

## 規格與選擇

程式：`catos/research_loss_limits.py`。只讀已跑完的 `BacktestResult` 與 K 線，不改成交、部位、損益，也不改 `catos/research.py`。

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 切日 | Asia/Taipei 00:00（UTC+8），用 `risk.taipei_day`；K 線歸入開盤時間所在的日 | 照 R1。4H、1H、15m、5m 的邊界都對齊台北午夜；不對齊的 K 線（例如 UTC 日線）會計數在 `straddling_bars` 並在介面提示 |
| 分母 | 當日第一根 K 線開盤時、成交前的權益：前一根收盤的部位以這根開盤價重估，扣掉這根開盤時結算的資金費 | R1 的基準是當日第一次觀測的權益。成交前取值，所以當天第一筆成交的手續費與滑價算在當天的虧損裡 |
| 當日最低權益 | 每根 K 線取兩點的較小者：成交後的部位以最不利價估值（多單最低價、空單最高價），餘額用收盤資金費之前的；以及收盤權益（資金費之後）。再和分母取較小者 | 和保證金模型同一個最不利價慣例。開盤成交前的權益不需要另外算：成交後在最不利價的權益一定不高於它（手續費與滑價只會減少權益） |
| 當日虧損 | （分母 − 最低權益）÷ 分母 | 規格 |
| 觸發 | 虧損 >= 門檻（剛好等於也算） | 和 `catos/risk.py` 的 `loss_reasons` 相同（`loss <= -limit`） |
| 門檻 | 現行預設讀 `risk.Limits()`（目前 10%／20%）；新預設 5%／10% 寫在本模組，標明「尚未套用到風控」 | 新預設還沒進 `risk.py`；上線時把常數刪掉、改讀 `risk.Limits()` |
| 強平或權益 <= 0 | 那天算觸發所有門檻，之後的日子不再計數；`stopped` 寫明日期與原因 | 規格。沒有保證金模型時（合成資料）權益跌破 0 之後只是算術延伸 |
| 每年天數 | 觸發天數 × 365 ÷ 涵蓋的台北日數（首日到末日，含頭尾） | 首日與末日可能只涵蓋部分時段，不另外修正 |
| 清單 | 每個門檻最多列 50 天，`truncated` 標示是否截斷 | 控制輸出大小 |

不做的事：

- 不模擬鎖存。實盤觸發 Soft 後當天停止增倉、Hard 會清倉，之後的損益會不同。
- 不套用單幣曝險上限（新預設 0.5 倍權益）。部位大小照策略本身，所以槓桿高於 0.5 倍的策略觸發次數會比上限上線後多。
- 不扣外部資金流（回測沒有入出金）。

會高估觸發次數的地方：同一根 K 線一律假設先碰到不利端；用成交價高低點代替標記價格。

## 輸出

- 回測結果 JSON 的 `daily_loss_limits`：`days_evaluated`、`span_days`、`years`、`first_day`、`last_day`、`max_daily_loss`（日期、虧損 %、分母、最低權益、最低點那根 K 線的開盤時間）、`stopped`、`straddling_bars`、`thresholds`（`current`／`proposed` 各有 Soft、Hard 的 `days`、`per_year`、`first_day`、`listed`、`truncated`）、`notice`。
- HTML 報表的「套用 Soft／Hard 日損門檻的觸發次數」表格。
- 回測頁「套用 Soft／Hard 日損門檻的觸發次數」面板；2026-11-12 之前的舊結果顯示「舊紀錄沒有日損門檻診斷」。
- `engine_sha256` 納入 `catos/research_loss_limits.py`，所以這次改動後既有結果的 provenance 雜湊會變（同保證金模型那次）。

## 驗證（2026-11-12，開發者自測，未經獨立驗收）

單元測試 `tests/test_research_loss_limits.py`（12 個）：門檻讀自 `risk.Limits()`、剛好等於門檻會觸發、略低於門檻不觸發、台北午夜切日（同一個 UTC 日拆成兩個台北日）、新一天的分母、空單用最高價、強平當天算觸發且之後停止、無保證金時權益 <= 0、沒有部位的日子、每年天數與清單上限、收盤資金費不算進最不利點的餘額、報表列。

4H 五年實跑（`execute_request` 純計算、不提交任務；本金 10,000、taker 0.0005、滑價 2 bps、保證金模型啟用）：

和 `docs/next-steps.md` 的上限估計（假設整天 0.5 倍滿倉在不利方向，每年 Soft 4.4 天、Hard 0.2 天）對照：

- 兩個策略的新 Soft 都低於上限估計。順勢策略不是每天滿倉，也不會一直站在不利方向，合理。
- 時間序列動能的新 Hard 每年 0.25 天，略高於上限的 0.2：2025-10-11（BTC 10 月 10 日夜間急跌）單日虧 11.53%，表示它當時的部位超過 0.5 倍權益。回測沒有套用單幣上限，上限上線後這天的虧損會變小。
- 用同一份資料以同樣假設重算的上限是每年 Soft 6.4 天、Hard 0.4 天（每個台北日取開盤到最低、開盤到最高較大的一邊，乘 0.5 倍）；和 next-steps 的 4.4／0.2 不同，原估計的算法沒有記錄，差異來源不確定。兩個策略的結果在兩種上限之下的結論相同。
