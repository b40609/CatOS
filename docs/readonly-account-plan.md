日期：2026-09-13。狀態：規劃交付，尚未啟動帳戶存取。使用者指定本模型負責規劃／開發，另一模型負責核對、review 與執行驗證；本輪不執行測試或宣稱驗證通過。

## 基線與目標

使用者回報 I-a 16／16、P6 18／18、受影響模組合計 113 tests 通過，且 diff 格式檢查通過；這是交接基線，未由本輪重驗。P6 正式預設已確認為 mark／earlier／cancel_confirm，ratio=0% 不啟用；UNKNOWN 禁增倉並告警。

I-b 要回答的是：指定帳戶實際資料能否正確解碼、保留來源與覆蓋證據，並找出不一致之處。I-b 不會放行交易、清除 latch、接管陌生部位、改寫執行帳本或把報告當成 J 的交易資格。

下表沿用 [I-a 映射](okx-readonly-contract.md)，是開發 allowlist 草案，不是本輪重新查證的官方規格。另一模型須核對指定地區／Demo 支援、各端點參數、分頁方向、限流與歷史保留期後才形成採集設定。

## 保存與隱私契約

建議採集輸出放專案外、使用者明示的本機目錄；開發用合成 fixtures 可放 repository。正式输出路徑未指定前，不錄製帳戶資料。

只保存欄位 allowlist 內、對帳所需的 JSON 資料：manifest、標準化 facts、discrepancies。金融值保留十進位字串，時間為明示單位。manifest 保存帳戶代稱、環境、端點別名、開始／完成時間、頁序／游標證據、來源時間語義、接收時間、缺頁原因、內容 digest 及程式版本。

不保存 API Key、Secret、Passphrase、簽名、授權 headers、完整請求 dump 或未篩選原始回應。uid／mainUid 與委託／成交／帳單 ID 以同批一致的假名保存，保留去重及關聯；只有記憶體保留必要原始 ID 供受限補查。保留子帳戶關係判定，不因脫敏丟失該證據。未授權的錯誤 body 不原樣寫入日誌。

本地檔案仍含私人帳務，即使假名化也不屬公開資料。預設不上传、不中途外送、不寫入 Git；不自行刪除使用者資料。輸出以完成標記區分完整與中斷批次，不用檔案存在或空清單當完整證據。

## 對帳與驗收出口

完整性是按資料來源與時間窗建立的證據，不是 API 回覆 code=0。達到頁數／時間上限、重複游標、錯誤或缺頁即標 incomplete；不將已取得部分資料丟棄或默認補零。

資料來源之間不具有原子快照保證。須保留開始／結束觀測與重疊查詢差異；無法收斂就交付不完整報告，不自行放寬新鮮度。首次執行的操作預算與資料可交易年齡是兩種不同設定，不能混用。

I-b 驗收由另一模型出具：實際帳戶／環境是否匹配、已核對端點、資料涵蓋區間、已完成與未完成案例、差異列表及限制。不以空倉或空測試帳戶聲稱驗證過真實成交／費用／保護觸發生命週期。未知資金流分類、缺失 E_0、陌生責任及 P6 觸發後子單缺口保持明示，不自行定案。
