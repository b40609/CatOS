# catOS 開發規約與工程守則

本文檔記錄 catOS 專案的開發原則、對話規範與架構邊界約束。

## 1. 語言與溝通原則

- **繁體中文溝通**：所有回覆、文件、註解及 UI 顯示文字預設使用繁體中文（台灣習慣用語）。
- **標準專業用語**：用戶為專業交易者（OKX KOL），非全職軟體工程師。全專案嚴格對齊 OKX App 標準交易術語與量化業界通用標準詞彙（如 CCXT、TradingView、Jesse），**嚴禁自創工程黑話**。
- **提案格式**：討論設計選項時，提供清楚的「建議」與「另一活路」，讓用戶能直接以「全收建議」或「第 n 改」做決策。

## 2. 第一版 (V1) 架構邊界與核心紅線

- **唯一真實通道**：第一版僅支援 **OKX 模擬盤**（Demo API Key，強制帶 x-simulated-trading: 1 標頭）過夜真下單，絕不碰實盤真錢，不跑純紙上虛擬撮合。
- **AI 權限限制**：AI 與 MCP 僅用於輔助生成策略插件、回測、調參，**絕對不能直接下單**、不得管理金鑰、不得觸發全平。
- **停損強制掛交易所**：所有停損均為標記價觸發的交易所端條件單（以持倉均價計算虧損百分比），不在本機軟止損。
- **單一交易對排他**：同一個合約代碼（如 BTC-USDT-SWAP）在同一時間只能有一個機器人處於運行中。
- **OKX App 狀態同步**：交易者在手機 OKX App 手動平倉後，機器人自動同步轉為 停機 · App 已平倉，絕不二次反向開倉。
- **狀態機標準術語**：生命週期狀態一律採用：待機、載入中、運行中、異常 · 連線中斷、停機 · 策略運算錯誤、停機 · App 已平倉。

## 3. 前端解耦護欄

- **前端尚未定案**：目前前端視覺風格與具體框架（Vue 3 / React）保留開放，尚未定案。
- **嚴格解耦**：後端一律以標準 REST API + SSE 事件流對外提供服務，後端代碼中不得擅自寫死特定前端框架依賴。
- **靜態託管**：預留 src/web/ 目錄，未來前端編譯之靜態產物放入後由 FastAPI 一體化掛載託管。

## 4. 交易術語規範

- **廢除自訂黑白名單**：無需維護瑣碎的黑名單或白名單表格。
- **唯一依歸**：全專案（包括程式碼變數、API 欄位、UI 文案、日誌記錄與對話溝通）**嚴格對齊 OKX App 標準交易術語與業界開源量化標準用詞（如 CCXT、TradingView、Jesse）**，杜絕自創工程黑話與非標準縮寫。

## 5. 技能調用守則 (Skills Rules)

本專案全面採用 .agents/skills/ 下的 Matt Pocock 正統工程工作流：

- **新功能與需求訪談**：使用 /grill-with-docs 或 /grilling 深入訪談對齊。
- **規格擬定**：使用 /to-spec 產出規格書至 .scratch/。
- **任務分解**：使用 /to-tickets 將規格拆解為具備阻擋依賴的 Tracer-bullet 垂直切片任務票。
- **程式碼實作**：使用 /implement，強制執行 TDD 紅綠燈循環，並以 /code-review 進行雙軸審查（標準 + 規格吻合度）。
- **除錯**：遵循 /diagnosing-bugs 流程，先建立可重現 Bug 的單一指令回饋迴圈，禁止憑空猜測假說。
- **流程指引**：不確定下一步時使用 /ask-matt。
